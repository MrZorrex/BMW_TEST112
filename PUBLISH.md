# Публикация в Яндекс Играх

Игра «Перекуп BMW» / «BMW Reseller» — single-file HTML5 (React + Vite, `vite-plugin-singlefile`).
Все изображения встроены в бандл data-URI, внешних запросов и ссылок нет (п. 8.4.2).
Языки игры: **русский и английский** (автоопределение через SDK + ручной переключатель).

## Сборка

```bash
npm ci
npm run build:yandex
```

Одна команда делает всё: `vite build` → проверка пакета
(`scripts/validate-yandex.mjs`: тег SDK, `YaGames.init()`, Loading/Gameplay API,
реклама, язык, отсутствие внешних запросов, обе локали) → упаковка
→ проверка архива. Если валидатор нашёл проблему — сборка останавливается
с понятным сообщением, битый пакет в Консоль не уйдёт.

Изображения встроены в исходник (`src/assets-data.ts`) — отдельный шаг для них не нужен.

Готовый архив: `publish/bmw-clicker-yandex.zip` (в корне архива — `index.html`, п. 1.22;
размер файлов далеко ниже лимита 100 МБ, п. 1.21). Локальная проверка: `npm run dev`.

> ⚠️ В Консоль загружается **только** `publish/bmw-clicker-yandex.zip`.
> Файл `pc-build/index.html` — автономная версия для ПК **без SDK** (он там
> специально вырезан): загруженный в Консоль, он получает отказ
> «Не встроено SDK» по п. 1.1. Не перепутайте файлы!

## П. 2.14 — автоопределение языка: как устроено и как проверить

Требование: язык определяется **через SDK во время запуска, а не в процессе игры**,
и сделан он должен быть у всех игр (даже с одним языком). Индикатор `文` на
debug-панели зеленеет в момент обращения к `ysdk.environment.i18n.lang`.

Порядок выбора стартового языка — один источник правды `resolveStartLang()`
(`src/i18n/index.ts`), его используют и бут, и игровое состояние:

1. **Ручной выбор игрока** (`lang` + `langPinnedOn` в сейве) — пока язык платформы не менялся (п. 6.9).
2. **Автоопределение SDK** — `environment.i18n.lang`; на платформе он **важнее языка из
   сейва**. Это ключевой момент: `lang` попадает в сохранение при любом автосейве, и
   если бы он имел безусловный приоритет, при следующем запуске (и при моке языка на
   debug-панели) игра оставалась бы на языке прошлого запуска → вердикт
   «язык не переключился» и отклонение.
3. **Вне платформы** (локальная разработка, `pc-build/`) — сохранённый язык, затем язык браузера.
4. Неизвестный код → резервный набор из доки: `ru` для be/kk/uk/uz, иначе `en`.

Что ещё закрыто по этому пункту:

- язык применяется к документу **до первого рендера** React: `<html lang>`, `title`,
  `meta description`, формат чисел и текст загрузочной заглушки (`applyLangToDocument`);
- заглушка загрузки локализована и до ответа SDK — синхронным инлайн-скриптом в
  `index.html` (иначе на EN/TR-доменах первые кадры показывали бы русское
  «Прогреваем мотор»; дока это допускает, но проверка смотрит именно на старт);
- автоопределение не «догоняется» по ходу игры: язык читается один раз, слушателей
  смены языка нет;
- `<meta name="google" content="notranslate">` + `translate="no"` — браузерный
  автоперевод не должен портить уже переведённый интерфейс.

### Проверка перед отправкой на модерацию

1. Локально: `npm run dev`, открыть с `?debug-mode=16` на хостинге Яндекс Игр
   (или через «Открыть с debug-панелью» в Консоли) — индикатор `文` должен стать
   зелёным на загрузке, а не после нажатия «Играть».
2. Смена языка: **SDK mocks ⚒️ → En/Ru** при уже имеющемся сейве — игра обязана
   открыться на выбранном языке (проверка `langPinnedOn` это и разрешает: пин
   снимается, когда язык платформы отличается от языка, на котором пин ставился).
3. Ручной переключатель (глобус в шапке): выбор языка применяется мгновенно,
   подписан на языке самого пункта («🇷🇺 Русский» / «🇬🇧 English») — п. 6.9.

> Примечание к старым сейвам: сохранения, созданные до введения `langPinnedOn`,
> не содержат отметки о ручном выборе, поэтому при первом запуске после обновления
> язык один раз берётся из SDK (это и нужно по п. 2.14). Дальше выбор игрока снова
> запоминается.


## Отказ «Не встроено или некорректно встроено SDK» (п. 1.1) — чек-лист

Такая формулировка означает, что платформа не увидела работающий SDK в
загруженном файле. По коду игра готова (см. таблицу выше), поэтому чаще всего
причина — в загруженном пакете, а не в исходниках. Проверьте по порядку:

1. **Что загружено в Консоль.** Должен быть архив `publish/bmw-clicker-yandex.zip`
   из свежей сборки (`npm run build:yandex`) или из Release `latest-build`.
   Типичные ошибки:
   - загружен `pc-build/index.html` (ПК-версия **без SDK** — отказ гарантирован);
   - загружена старая сборка, скачанная до исправлений SDK;
   - архив упакован вручную так, что `index.html` лежит во вложенной папке
     (должен быть строго в корне, п. 1.22) — наш `scripts/pack.mjs` делает правильно.
2. **Тип интеграции.** Архив в Консоль (сервер Яндекса) → тег `/sdk.js`, он уже
   в `index.html`. Если игра хостится на своём домене через iframe → нужен
   абсолютный путь `https://sdk.games.s3.yandex.net/sdk.js`: игра догружает его
   автоматически (`ensureSdkScript()` в `src/game/yandex.ts`), но лучше проверить.
3. **Проверка с debug-панелью.** Откройте черновик через «Открыть с debug-панелью»
   (или добавьте `?debug-mode=16` к ссылке на игру) и убедитесь:
   - индикатор лоадера — `IT` (инициализирован верно), а не `W` или `IF`
     (`IF` = старый путь SDK — у нас актуальный `/sdk.js`);
   - в консоли есть сообщение `Initialized` от SDK;
   - индикатор `文` (i18n) зеленеет **на загрузке**, до нажатия «Играть»;
   - в консоли нет красных ошибок (п. 6.4).
4. **Старт игры.** Игра обязана открываться за секунды: инициализация SDK,
   хранилище, игрок и облако ограничены таймаутами (`withTimeout`), рендер
   и `LoadingAPI.ready()` никогда не ждут висящую сеть дольше ~10 секунд.
   Бесконечная заглушка «Прогреваем мотор» = повод смотреть консоль браузера.
5. **Повторная отправка.** После загрузки исправленного архива дождитесь
   обработки новой версии черновика и только потом жмите «Отправить на модерацию» —
   иначе на проверку уйдёт предыдущий файл.

## Консоль разработчика — пошагово

1. Создайте профиль в [Консоли](https://games.yandex.ru/console), укажите язык связи.
2. Заключите договор: РФ юрлицо/ИП — Единая лицензионная схема прямо в Консоли;
   иначе — регистрация в [РСЯ](https://partner.yandex.ru/) как самозанятый/ИП + реквизиты.

### 2. Черновик игры

1. **Архив** — загрузите `publish/bmw-clicker-yandex.zip` или ZIP из GitHub Release.
2. **Название** — RU: «Перекуп BMW», EN: «BMW Reseller» (идентично игре, п. 5.1.3).
3. **Языки** («Игра переведена на») — русский и английский. Карточку на других
   языках можно получить через **AI-описания** (опция включена до первой публикации;
   внутриигровые тексты уже переведены вручную).
4. **Облачные сохранения** — включите опцию «Игра использует облачные сохранения» (п. 1.11;
   игра хранит прогресс через `player.setData/getData`, ключ `save`).
5. **Категории** — «Казуальные» / «Кликеры» (содержание соответствует жанру, п. 2.3).
6. **Возрастной тег** — 6+ (п. 2.7).
7. **Иконка** 512×512 и **обложка** — без скриншотов из игры (п. 5.6), без рамок/скруглений (п. 8.3.3).
8. **Скриншоты** — реальный геймплей ≥70% кадра (п. 5.1.1.2), желательно на обоих языках.
9. **Поддерживаемые платформы** — десктоп + мобильные; **ориентация** — любая
   (игра адаптирована под портрет и альбом, п. 1.10).
10. Заполните **Об игре** и **Как играть** на обоих языках (примеры ниже, п. 2.2).

### 3. Монетизация

1. Подключите рекламную монетизацию (РСЯ → реквизиты → оферта акцептована).
2. Полноэкранная и rewarded-реклама вызываются игрой через `ysdk.adv` — настройки в Консоли не требуются.
3. Стики-баннеры (вкладка «Реклама») опциональны; игра занимает всю доступную область.

### 4. Инап-покупки (вкладка «Инап-покупки»)

Код уже готов: покупки обрабатываются на клиенте (`getPayments()` без `signed`),
есть консумация и проверка необработанных покупок при каждом запуске (п. 1.13.1),
защита от двойной выдачи по токенам, выдача фиксируется до консумации.

**Важно:** если покупки ещё не подключены для аккаунта — заранее проверьте схему
сотрудничества (Профиль → Единая лицензионная схема): при статусе «Не подключён» /
«Отключён» вне ЕЛС нужно отдельно запросить подключение покупок письмом на
games-partners@yandex-team.ru (название + ID игры) после акцепта оферты РСЯ.
Без этого игра с покупками не пройдёт модерацию.

Добавьте товары (id строго как в коде — `src/data/products.ts`, названия
и описания — на русском И английском, описания ≤200 символов):

| ID | Тип | Название RU / EN | Описание RU / EN |
|---|---|---|---|
| `cash_pile` | расходный (консумируется) | Горсть наличных / Handful of cash | Мгновенно выдаёт наличные: 35% от цены следующей машины. Можно покупать многократно. / Instantly pays out cash: 35% of the next car’s price. Can be bought repeatedly. |
| `vip_dealer` | постоянный (не консумируется) | Статус «Перекуп года» / “Flipper of the Year” status | Навсегда +25% ко всему доходу: клик, пассив и автокликер. Действует во всех кругах. / Forever +25% to all income: clicks, passive and autoclicker. Works across all laps. |

- **Стоимость в янах** — целое число (например, 39 и 99 ян; ориентируйтесь на метрики).
- **Иконка** — PNG 256×256 на каждый товар или дефолтная в «Настройках».
- ⚠️ Список активных покупок в Консоли должен совпадать с игрой (п. 1.13.6):
  каталог в игре строится из SDK — удалили товар в Консоли → он исчезнет из игры автоматически.
  Если покупки не нужны — просто не добавляйте их: кнопка магазина не появится (п. 1.12
  при этом закрыт рекламой).
- **Тест**: добавьте свой логин Яндекс ID в «Список логинов для тестовых покупок»
  (Инап-покупки → Настройки) — тестовые покупки бесплатны, но обязательно
  консумируются игрой, иначе модерация не пройдёт (п. 1.13.1).

  индикатор 文 — зелёный на старте. Ручной переключатель (глобус в шапке) меняет
  язык мгновенно.
- **Ориентации**: проверьте портрет и альбом на телефоне и десктопе — главный экран
  без прокрутки, элементы не обрезаются; управление с клавиатуры (Пробел/Enter).
- В DevTools-консоли не должно быть ошибок (п. 6.4).
- Отправьте на модерацию (3–5 рабочих дней). При отказе — причины придут на почту
  из профиля разработчика.
